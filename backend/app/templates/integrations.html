Connect your monitoring tools

OpsPilot exposes webhook endpoints so any alerting tool can create incidents and trigger the agent automatically — no dashboard interaction required.

How it works

  1. Your monitoring tool sends an HTTP POST to one of the webhook endpoints below.
  2. OpsPilot creates an incident from the payload automatically.
  3. With ?auto_run=true, the agent starts immediately — no human needed to trigger it.
  4. If the agent recommends a risky action, it is blocked and an approval request is created.
  5. Your team approves or rejects from the Approvals board or the REST API.

Authentication header

Pass your token on every webhook request:

X-Webhook-Token: opspilot_wh_<your-token>

Each token is tied to a name. You can generate multiple tokens — one per integration — and revoke them independently.

Tokens are hashed on write. The raw value is only shown once at creation time.

Prometheus Alertmanager

Recommended

Add a receiver to your alertmanager.yml. Each firing alert becomes one incident. Pass auto_run=true to start the agent without any manual step.

receivers:
  - name: opspilot
    webhook_configs:
      - url: '{{ base_url }}/api/webhooks/alertmanager?auto_run=true'
        headers:
          X-Webhook-Token: 'opspilot_wh_your-token-here'
        send_resolved: false

route:
  receiver: opspilot
  group_wait: 10s
  group_interval: 5m
  repeat_interval: 1h

Set send_resolved: false so OpsPilot only receives firing alerts, not resolution events.

Grafana Alerts

Generic webhook

In Grafana, go to Alerting → Contact points → Add contact point. Choose Webhook and use the URL below.

URL:    {{ base_url }}/api/webhooks/generic?auto_run=true
Method: POST
Header: X-Webhook-Token = opspilot_wh_your-token-here

Grafana alert payload is automatically mapped:

Grafana field

title or ruleName

→ OpsPilot field

title

Grafana field

severity or level

→ OpsPilot field

severity (critical / high / medium / low)

Generic webhook — any tool

Any tool that can send JSON over HTTP works. The minimal required payload is:

{
  "title": "Memory spike on worker-3",
  "severity": "high",
  "description": "RSS over 90% for 10 minutes on worker-3.",
  "source": "datadog"
}

Test it now from your terminal:

curl -X POST "{{ base_url }}/api/webhooks/generic?auto_run=true" \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Token: opspilot_wh_your-token-here" \
  -d '{
    "title": "Memory spike on worker-3",
    "severity": "high",
    "description": "RSS over 90% for 10 minutes on worker-3.",
    "source": "datadog"
  }'

Response:

{"incident_id": 7, "status": "triaging", "auto_run": true, "view_url": "/incidents/7"}

REST API — full programmatic control

Every action available in the dashboard is also available via the REST API. The interactive API docs are at {{ base_url }}/docs.

POST

/api/incidents

Create an incident manually.

POST

/api/incidents/{id}/run-agent

Trigger the agent. Returns immediately, agent runs in background.

GET

/api/incidents/{id}

Poll for agent completion. Status changes from triaging when done.

POST

/api/approvals/{id}/approve

Approve a risky action programmatically (e.g. from Slack bot or CLI).
